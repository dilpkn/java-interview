## Что такое _ООП_?
__Объектно-ориентированное программирование (ООП)__ — методология программирования, основанная на представлении программы в виде совокупности объектов, каждый из которых является экземпляром определенного класса, а классы образуют иерархию наследования.

[к оглавлению](#ООП)

## Назовите основные принципы _ООП_.
+ _Инкапсуляция_ - сокрытие реализации.
+ _Наследование_ - создание новой сущности на базе уже существующей.
+ _Полиморфизм_ - возможность иметь разные формы для одной и той же сущности.
+ _Абстракция_ - набор общих характеристик.
+ _Посылка сообщений_ - форма связи, взаимодействия между сущностями.
+ _Переиспользование_- все что перечислено выше работает на повторное использование кода.

Это единственно верный порядок парадигм ООП, так как каждая последующая использует предыдущие.

## Что такое _«инкапсуляция»_?
__Инкапсуляция__ – это механизм, позволяющий объеденить поля и методы для работы с ними в один класс и защитить данные от некоректного вмешательства

Пример:
```java
public class AbstractPhone {

    private int year;
    private String company;
    public AbstractPhone (int year, String company) {
        this.year = year;
        this.company = company;
    }
    private void openConnection(){
        //findComutator
        //openNewConnection...
    }
    public void call() {
        openConnection();
        System.out.println("Вызываю номер");
    }

    public void ring() {
        System.out.println("Дзынь-дзынь");
    }

}
```

## Что такое _«наследование»_?
__Наследование__ – это свойство системы, позволяющее описать новый класс на основе уже существующего с частично или полностью заимствующейся функциональностью.

Класс, от которого производится наследование, называется _предком_, _базовым_ или _родительским_. Новый класс – _потомком_, _наследником_ или _производным_ классом.

[к оглавлению](#ООП)

## Что такое _«полиморфизм»_?
__Полиморфизм__ – это способность объектов с одинаковым интерфейсом иметь разную реализацию, а вызывающему коду не нужно знать, с объектом какого типа он работает

_Полиморфная переменная_, это переменная, которая может принимать значения разных типов, а _полиморфная функция_, это функция, у которой хотя бы один аргумент является полиморфной переменной.
Виды полиморфизма:
+ _ad hoc_, функция ведет себя по разному для разных типов аргументов (например, функция `draw()` — рисует по разному фигуры разных типов);
+ _параметрический_, функция ведет себя одинаково для аргументов разных типов (например, функция `add()` — одинаково кладет в контейнер элементы разных типов).
+ _полиморфизм подтипов_, дочерний класс может использоваться везде, где ожидается родительский

_Абстракция_ - это выделение главных характеристик объекта и сокрытие ненужного

## Что представляет собой _«обмен сообщениями»_?
_Обмен сообщений_ - фундаментальный механизм взаимодействия между объектами, при котором один объект запрашивает выполнение у другого, отправляя ему сообщение.

Объекты не вызывают методы друг друга напрямую - они отправляют друг другу сообщения.

[к оглавлению](#ООП)

## Расскажите про основные понятия ООП: _«класс»_, _«объект»_, _«интерфейс»_.
**_Класс_** — это шаблон того, каким будет объект. Он определяет:

Какие данные (поля) будут у объекта
Какое поведение (методы) будет у объекта

**_Объект_** — это конкретный экземпляр класса, созданный в памяти во время выполнения программы. У каждого объекта:

Свои собственные значения полей
Общее поведение (методы), определенное классом

__Интерфейс__ – это совокупность всех публичных методов, свойств и конструкторов, которые класс предоставляет для взаимодействия.

## В чем заключаются преимущества и недостатки объектно-ориентированного подхода в программировании?
Плюсы ООП
+ Моделирование реального мира — код отражает естественное мышление о сущностях и их взаимодействиях
+ Повторное использование — наследование и композиция позволяют не писать один и тот же код многократно
+ Инкапсуляция и абстракция — скрывает сложность, упрощает использование и защищает данные
+ Полиморфизм — добавлять новые типы можно без изменения существующего кода
+ Поддерживаемость — изменения локализованы, код легче тестировать и читать
+ Масштабируемость — большие системы легче организовывать и развивать
+ Патерны проектирования — богатая экосистема проверенных решений типовых задач

Минусы ООП
+ Избыточность — много шаблонного кода (геттеры, сеттеры, конструкторы) для простых задач
+ Сложность иерархий — глубокое наследование трудно понимать и поддерживать
+ Хрупкость базового класса — изменение родителя может сломать всех потомков
+ Производительность — виртуальные методы, динамическая диспетчеризация, лишние абстракции дают накладные расходы
+ Проблемы с многопоточностью — изменяемое состояние объектов требует сложной синхронизации
+ Неестественность для некоторых задач — обработка данных, математика, конвейеры преобразований лучше ложатся на функциональный стиль
+ Риск перепроектирования — соблазн создавать избыточные абстракции там, где достаточно простого кода
+ Тесная связанность — без дисциплины (интерфейсы, DI) объекты жестко привязываются друг к другу, усложняя тестирование

## В чем разница между _композицией_ и _агрегацией_?
Ассоциация обозначает связь между объектами. Композиция и агрегация — частные случаи ассоциации «часть-целое».

_Композиция_ — вложенный объект не может существовать без владельца (владелец создает и уничтожает его):

```java
class Engine {
    private final int horsepower;
    
    Engine(int horsepower) {
      this.horsepower = horsepower;
    }
}

class Car {
    private final Engine engine; // Engine живёт и умирает вместе с Car
    
    Car(int horsepower) {
        this.engine = new Engine(horsepower); // Car сам создаёт Engine
    }
}
```

_Агрегация_ — вложенный объект существует независимо, передается извне:

```java
class Driver {
    private final String name;
    
    Driver(String name) {
      this.name = name;
    }
}

class Car {
    private Driver driver; // Driver может существовать без Car
    
    Car(Driver driver) {
        this.driver = driver; // Car получает Driver извне
    }
}
```

Коротко: если `new` внутри класса — композиция, если объект приходит снаружи — агрегация.

Предпочтительнее использовать агрегацию и внедрять зависимости через конструктор. Это автоматически делает код тестируемым и следует принципу Dependency Inversion из SOLID. Композицию стоит применять, когда есть чёткая причина "спрятать" создание объекта внутрь класса.

## Что такое _статическое_ и _динамическое связывание_?
Статическое и динамическое связывание — это механизмы, определяющие когда и как вызываемый метод связывается с его реализацией.

**Статическое связывание** (Static Binding / Early Binding)
Связывание происходит на этапе компиляции. Компилятор точно знает, какой метод будет вызван.

Когда применяется:
Статические методы (static)
Приватные методы (private)
Финальные методы (final)
Перегруженные методы (overloading) — выбор версии метода по типам аргументов
Конструкторы

**Динамическое связывание** (Dynamic Binding / Late Binding)
Связывание происходит во время выполнения программы. Компилятор не знает, какой именно метод будет вызван — решение принимает JVM (или аналогичный механизм в других языках) на основе фактического типа объекта.

Когда применяется:
Виртуальные методы (не статические, не приватные, не финальные)
Переопределенные методы (overriding)
Вызовы методов через интерфейсы

Статическое связывание — «я знаю, какой метод вызову, еще до запуска программы».
Динамическое связывание — «я узна́ю, какой метод вызывать, только когда программа выполнится, в зависимости от того, объект какого класса лежит в переменной».
